# 交互式架构网图可视化工具

**需求文档 v1.0**

---

# 1. 项目概述

## 1.1 项目目标

开发一个 **基于 Web 的交互式架构图可视化工具**，用于展示和维护系统组件之间的依赖关系。

该工具通过 **简单 JSON 数据** 描述图结构，并在网页中进行 **可视化展示与交互编辑**，适用于：

* 系统架构关系展示
* 模块调用关系分析
* 组件依赖维护
* 技术架构文档可视化

典型使用场景：

* 浏览器架构（如 Chromium）
* 微服务调用关系
* 组件依赖图
* 软件模块结构

---

# 2. 总体功能

系统提供以下核心能力：

1. **图结构可视化**
2. **节点管理（CRUD）**
3. **关系管理**
4. **力导向自动布局**
5. **节点拖拽**
6. **JSON 数据导入导出**

系统无需后端服务，完全运行于浏览器。

---

# 3. 数据模型设计

## 3.1 节点数据结构

系统使用 **JSON 数组**表示整个图结构。

每个节点结构如下：

```json
{
  "name": "NodeName",
  "relationships": ["TargetNode1", "TargetNode2"]
}
```

字段说明：

| 字段            | 类型       | 说明      |
| ------------- | -------- | ------- |
| name          | String   | 节点唯一名称  |
| relationships | String[] | 指向的下游节点 |

---

## 3.2 节点唯一性

* `name` 作为 **全局唯一标识符**
* 系统 **不使用 id 字段**

---

## 3.3 关系语义

`relationships` 表示：

```
当前节点 → 下游节点
```

示例：

```json
{
  "name": "Browser",
  "relationships": ["Renderer","Network"]
}
```

表示：

```
Browser → Renderer
Browser → Network
```

---

## 3.4 数据纯净性要求

导入导出数据 **必须保持纯净**。

允许字段：

```
name
relationships
```

禁止字段：

```
x
y
index
vx
vy
fx
fy
```

这些字段属于运行时布局信息，不能写入文件。

---

# 4. 可视化设计

## 4.1 节点样式

节点使用 **矩形结构**。

要求：

* 节点为矩形
* 矩形宽度根据 `name` 自动调整
* 节点文字居中
* 节点具有背景颜色
* 每个节点颜色可区分

示意：

```
┌─────────────┐
│   Browser   │
└─────────────┘
```

---

## 4.2 节点尺寸

矩形宽度规则：

```
width = name长度 × 字符宽度 + padding
```

高度固定。

---

## 4.3 关系连线

关系使用 **带箭头的有向边**。

表现规则：

* 直线连接
* 箭头指向 **目标节点**
* 箭头终点应 **贴近目标节点边缘**

示意：

```
A ─────▶ B
```

---

## 4.4 颜色策略

颜色规则：

1. **节点颜色**

   * 每个节点具有背景色

2. **连线颜色**

   * 根据 **目标节点** 进行区分
   * 指向同一节点的所有连线颜色一致

---

# 5. 布局系统

## 5.1 布局算法

系统使用 **力导向布局（Force-directed layout）**。

特点：

* 节点自动分散
* 自动减少重叠
* 自动形成可读结构

---

## 5.2 布局行为

布局规则：

| 行为   | 说明    |
| ---- | ----- |
| 节点之间 | 具有排斥力 |
| 连线   | 具有拉力  |
| 系统   | 自动居中  |

---

# 6. 交互功能

## 6.1 节点拖拽

用户可以拖拽节点改变位置。

要求：

* 节点可自由拖动
* 连线实时更新
* 箭头实时更新

---

## 6.2 节点选择

点击节点后：

系统自动：

* 选中节点
* 在侧边栏显示节点信息

填充内容：

```
name
relationships
```

---

# 7. 节点管理（CRUD）

系统支持节点的 **增删改查**。

---

## 7.1 新增节点

用户输入：

```
节点名称
relationships
```

点击 **新增 / 更新**：

行为：

* 若节点不存在 → 新建节点
* 若节点已存在 → 更新节点

---

## 7.2 更新节点

修改：

```
relationships
```

点击保存后：

* 更新节点关系
* 重新渲染图结构

---

## 7.3 删除节点

删除节点时系统需要：

1. 从节点列表删除
2. 清理其他节点中的引用

例如：

```
A → B
C → B
```

删除 B 后：

```
A
C
```

---

## 7.4 查询节点

查询方式：

* 点击节点

系统自动：

* 在表单中显示节点信息

---

# 8. 数据导入导出

## 8.1 JSON 导出

系统提供 **一键导出 JSON**。

导出要求：

* 数据格式化
* UTF-8 编码
* 文件名：

```
graph.json
```

---

## 8.2 JSON 导入

用户可导入 JSON 文件。

流程：

1. 用户选择文件
2. 系统解析 JSON
3. 更新数据
4. 重新生成布局

---

## 8.3 数据校验

导入数据必须满足：

* JSON 格式
* 节点包含：

```
name
relationships
```

否则导入失败。
